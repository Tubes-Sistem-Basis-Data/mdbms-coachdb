# Keputusan Desain

Keputusan lintas komponen untuk versi minimal mDBMS CoachDB. Perubahan keputusan lewat PR berlabel `kontrak` dan dicatat juga di [`changelog-kontrak.md`](changelog-kontrak.md).

| No | Keputusan | Alasan | Komponen terdampak |
| --- | --- | --- | --- |
| 1 | **Granularitas lock multiple granularity (tabel dan baris).** Hirarki tabel ke baris (RID). Mode `IS`, `IX`, `S`, `SIX`, `X` dengan matriks kompatibilitas standar. Protokol Strict 2PL multigranularity, semua lock dilepas saat commit/abort selesai. QP tidak meminta intention lock; QP cukup memanggil `validate_object` dengan `ResourceId` daun dan `Action`, CCM yang mengambil intention lock di tabel. `LockMode` tipe internal CCM. Protokol timestamp memakai item yang sama (tabel atau baris) sebagai unit read-TS/write-TS. | `S` tabel saat scan bertabrakan dengan `IX` dari INSERT transaksi lain, sehingga phantom tercegah tanpa predicate lock. QP tetap sederhana karena tidak perlu tahu hirarki lock. | CCM, QP |
| 2 | **WAIT non-blocking.** `validate_object` langsung mengembalikan `AccessResponse(WAIT)`. CCM menyimpan posisi antrean, QP mengulang permintaan yang sama dengan jeda kecil (`WAIT_RETRY_SECONDS`, 50 ms) sampai `ALLOWED` atau `ABORTED`. Pengulangan idempoten dan tidak menghasilkan log ganda. | Thread QP tidak tertahan di dalam CCM, deadlock detection tetap bisa berjalan, dan kontrak tidak butuh callback. | CCM, QP |
| 3 | **WAL dan LSN.** Setiap izin WRITE menghasilkan tepat satu `LogRecord(DATA)`. LSN dikembalikan di `AccessResponse.lsn` lalu diteruskan QP ke `SM.insert/update/delete(..., lsn)`. SM menyimpan `page_lsn` dan memanggil `flush_log(page_lsn)` sebelum menulis page dirty. | Log selalu ditulis sebelum data, dan SM tahu batas log yang harus permanen untuk tiap page. | CCM, FRM, QP, SM |
| 4 | **INSERT dua langkah:** `SM.allocate_rid` → `CCM.validate_object(WRITE, DataChange(INSERT, NO_RECORD, values))` → `SM.insert(t, rid, values, lsn)`. Jika tidak ALLOWED, `SM.release_rid(rid)`. | Lock dan log butuh RID sebelum baris benar-benar ditulis. | QP, SM, CCM |
| 5 | **Abort satu alur** untuk semua penyebab (user, deadlock, timestamp). CCM menulis `ABORT_REQUEST`, memanggil `FRM.rollback`, lalu menulis `ABORT` + `flush_log` setelah rollback sukses, baru lock dilepas. | Satu jalur lebih mudah diuji dan lock tetap menjaga data selama undo. | CCM, FRM |
| 6 | **Crash di tengah rollback tanpa CLR.** Undo di SM idempoten: undo INSERT = hapus jika ada, undo DELETE = insert di RID yang sama jika belum ada, undo UPDATE = tulis before-image. | Undo bisa diulang dengan aman saat recovery tanpa format log tambahan. | FRM, SM |
| 7 | **Protokol default CCM `LOCK_BASED`**, dipilih lewat `python main.py --protocol lock\|timestamp`. | Lock-based dikerjakan lebih dulu (M2), timestamp menyusul (M3). | CCM, main.py |
| 8 | **RID = `(table, page_id, slot)`.** | Cukup untuk menemukan baris langsung dan unik antar tabel. | SM, CCM, FRM, QP |
| 9 | **Index wajib B+Tree** (kesamaan dan rentang), Hash opsional. Sintaks `CREATE INDEX <nama> ON <tabel>(<kolom>) [USING BTREE\|HASH]`, default BTREE. | B+Tree melayani kedua jenis pencarian; Hash hanya kesamaan. | QO, QP, SM |
| 10 | **Join minimal Block Nested Loop Join** (`Join.algorithm = "BNLJ"`). Satuan biaya QO adalah jumlah transfer blok. | BNLJ selalu bisa dipakai untuk semua jenis kondisi; satuan blok sesuai materi kuliah. | QO, QP |
| 11 | **Parameter fisik default** di `common/config.py`: `BLOCK_SIZE = 4096`, `BUFFER_FRAMES = 64`, `DATA_DIR = "data"`, `HOST = "127.0.0.1"`, `PORT = 5440`. Group SM boleh mengubah nilai lewat `config.py`. | Satu sumber nilai untuk SM, QO (cost), dan QP (server). | SM, QO, QP |
| 12 | **Client-server lewat TCP socket**, protokol JSON per baris: request `{"session_id", "sql"}`, response `ExecutionResult` hasil `to_dict()`. Detail lain internal QP. | Mudah di-debug dan cukup dengan standard library. | QP |
| 13 | **`EXPLAIN <query>;`** di CLI memanggil `QO.explain`. | Menampilkan plan sebelum dan sesudah optimasi (QO-15) tanpa jalur khusus. | QO, QP |
| 14 | **SM tidak import FRM.** `main.py` memanggil `sm.set_log_flusher(frm.flush_log)`. | Memutus ketergantungan melingkar SM dan FRM. | SM, FRM, main.py |
